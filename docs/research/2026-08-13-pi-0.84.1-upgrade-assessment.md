# Pi 0.84.1 升级评估

日期：2026-08-13

## 结论

Hunter Pi 需要把 Pi Engine Release 从 `@earendil-works/pi-coding-agent@0.83.0` 更新到 `0.84.1`。截至本次核验，GitHub 最新 Release 和 npm `latest` 均为 `0.84.1`，二者绑定同一提交 `53fa77ccd8a279eb87e92294ef3687b03ff80112`。

最直接的兼容性变化是 JSON/RPC `message_update` 改为仅包含 `assistantMessageEvent` delta。累计 `message` 和 `assistantMessageEvent.partial` 已移除，`message_end.message` 是最终权威值。Hunter Pi 的 Provider 用量核算原本只读取最终 `message_end`，不依赖被移除字段；公开接口探针仍需新增 delta-only 合同，防止将旧线格式误判为兼容。

本结论只允许进入升级和分发验证，不构成 Stable、生产可用或日常使用验收。真实 Provider、真实用户仓库和现有用户状态均未用于本次评估。

## 公开接口影响

| 上游变化 | Hunter Pi 使用情况 | 处理 |
| --- | --- | --- |
| JSON/RPC `message_update` 仅输出 delta | 探针观察事件；Managed Change 的 Provider 用量只读取 `message_end` | 新增 JSON 与 RPC delta-only 合同；继续把 `message_end` 作为权威值 |
| `ModelsStreamTransforms` 更名为 `ModelsRequestTransforms` | 未导入 | 无代码迁移 |
| `ModelRegistry.getApiKeyAndHeaders()` 允许 `null` header | 未读取该返回值 | 无代码迁移 |
| `ModelRegistry.refresh()` 与 `ModelRuntime` 刷新接口调整 | 未调用这些接口 | 无代码迁移 |
| pi-agent-core v4 Session/Harness 接口替换 | Workflow Kernel 不依赖 Pi Session 作为规范工作流状态 | 保持领域边界，不引入 Pi 私有身份 |
| `tool_call` 阻断可带 `terminate` | 当前 Core Extension 不依赖该字段 | 暂不扩大功能声明 |

## 本地初步证据

升级前基线为 71 个测试文件、728 个测试通过。测试先要求 `0.84.1` 精确身份和 JSON/RPC delta-only 合同，确认在 `0.83.0` 上按预期失败。更新后，Windows 隔离 Git fixture 中的 Extension、JSON、RPC 和 SDK 探针通过；JSON 与 RPC 均观察到 `assistantMessageEvent`，且未观察到累计 `message` 或 `partial`，最终 assistant `message_end` 存在。相关 CLI、Doctor、插件资格和 Managed Change 回归为 8 个测试文件、83 个测试通过，类型检查通过。

完整 Windows/Ubuntu CI、Windows 安装分发、更新/回滚和发布后真实下载复验仍为 `PENDING`，应记录在单独的验证文档和 Evidence 中。
